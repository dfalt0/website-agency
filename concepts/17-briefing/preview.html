Your website is a long-running process. This brief says who runs it.

For owners and operators who need a custom website built, hosted, and kept alive without managing servers. Read the sections you need. Section 07 opens an engagement.

01

Scope

We design and write your site by hand, run it on infrastructure we operate, and stay on call after launch. One team, one ticket queue, one invoice. There is no hand-off to a hosting vendor.

Applies to: marketing sites, booking sites, small catalogs, member portals up to 5k users.

Note 1.1“Custom” means no page-builder or theme resale. You receive the repo.
02

Build procedure

  1. Intake. Goals, audience, current assets, constraints. Output: one-page spec.
  2. Structure. Sitemap and page contracts signed off before visuals.
  3. Design. Two directions, one chosen, revised twice.
  4. Build. Code in your repo; staging URL from day one.
  5. Acceptance. You run the checklist. We fix until it passes.
  6. Cutover. DNS moves. Old site kept warm for 14 days.
Typical durationSmall site: 3–5 weeks. Larger: scoped per page count.
03

Hosting runtime

Each site is a persistent deployment with its own environment, backups, and rollback. You can ask the runtime what it is doing at any time.

# what we run for you, expressed as commands you never have to type
$ site status acme-dental
● live      rev 41   region eu-central   uptime 99.98% (30d)
● tls       valid    renews in 52d
● backup    03:00 UTC daily, 30 retained
$ site deploy --from staging --gate checks
running: build, links, headers, visual-diff … passed
$ site rollback --to 40   # under 2 minutes
Note 3.2You get a read-only status page and a human. Commands are ours to run; results are yours to see.
